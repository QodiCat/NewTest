# 因构智采 · 本地 Web 系统

依据本目录 PRD、测试方式、UI.png 与 check_docs 的 18 份实际 DOCX 实现。PRD 提到的第 19 份文件当前目录未提供；不使用测试预期作为检测输入。

## 启动

需要 Node.js 24 或更新版本。在本目录执行：

```powershell
npm.cmd install
Copy-Item .env.example .env
npm.cmd start
```

打开 http://127.0.0.1:3000 。首次启动会导入 check_docs 文档、分类并导入两组规则。后续启动复用 `data/procurement.sqlite` 和 `data/uploads`，不会覆盖人工修改。完整备份 data 文件夹可保留原件、任务及日志。

演示账号 `reviewer`（审核）、`business`（业务）、`agency`（代理）、`audit`（只读监督）、`admin`（管理员）；初始密码均为 `LocalDemo2026!`。可在**首次启动前**在 `.env` 设置 `DEMO_PASSWORD`。已有账户密码不因修改环境变量而变化。默认仅监听本机，这是本地演示系统，未实现企业身份认证与人员管理，不宜直接向公网开放。

## 模型配置

后端始终按项目根目录的绝对路径读取 `.env`，每次模型请求读取最新内容，不依赖启动时所在目录。此修复首次加载需要重启原服务一次；之后修改配置保存即可生效。浏览器单文件 HTML 无权自动读取本地 `.env`，真实 AI 需要通过本地后端使用。

在 `.env` 中配置后重启：

```dotenv
AI_BASE_URL="http://localhost:11434/v1"
AI_MODEL="qwen3:8b"
AI_API_KEY=""
PORT=3000
HOST=127.0.0.1
```

兼容 OpenAI 风格 `POST {AI_BASE_URL}/chat/completions`，支持本地模型和兼容网关；地址也可填写完整的 `/chat/completions` 端点。只需配置上面三个变量，地址与模型名齐全后自动启用，无需额外启用开关；无需鉴权的本地服务可留空密钥。旧版 `LLM_*` 变量仍作为兼容回退，新版 `AI_*` 优先。默认超时为 120 秒，可选配 `AI_TIMEOUT_MS`。密钥不会发往浏览器或写入审计包。问答必须使用真实模型，支持连续追问，传递最近 10 轮上下文；无需先上传文件即可提问。已上传且可访问的制度片段会作为参考资料。地址错误、超时或鉴权失败时直接显示错误，不使用本地原文替代 AI 回答。其他确定性规则、文档编制与比对不依赖模型。

语义补充只接收路由选中的项目文档；对无法核验规则提供模型补充，引用必须在选定原文中逐字存在。模型故障会明确显示为部分完成，保留已完成规则，不伪造模型结论。真实模型尚未配置，因此本次未执行外部模型联调。

## 操作路径

Windows 单文件导出：运行 `node scripts/export-windows-html.mjs` 生成 `exports/因构智采_Windows单文件版.html`，可用新版 Edge／Chrome 双击打开，无需安装 Node。内置原始样例、界面、处理流程及文档导出，不含 `.env`、密钥或实际用户数据库。离线版不能直接使用服务器模型配置，可通过右下角入口进入本地服务。此命令用于产物导出，不执行测试。

“导出批注版”读取本次检测目标的原 DOCX，在原段落或表格行添加真正的 Word 批注。批注包含规则编号、结论、诊断、建议及跨文档基准原文；同一位置的多个检测点合并到一条批注，原有批注继续保留。无法精确定位的检测项集中批注在首页并明确说明。原正文、表格、样式、图片等包内内容保留，原始文件不被覆盖，下载文件名为“原文件名_批注版.docx”。功能在浏览器端处理，使用原有下载接口，无需新增后端接口；需新版 Edge／Chrome 的原生 DOCX 解压支持，不支持加密 DOCX 或 PDF。

检测报告工具栏的“导出诊断报告”直接下载当前任务的 DOCX，包含任务信息、结果汇总、全部检测点的结论、检查依据、整改建议、目标／基准原文及定位和材料版本。招标检测导出全部 15 条，评标报告核验按当前任务导出 7 条。文档在浏览器中根据已显示的报告生成，不依赖新增后端接口。

评标报告核验的检测报告和历史记录提供“一键 AI 处理”：约 6 秒后导出 `17_评标报告_复核版.docx`，以 01 项目登记、09 招标发布版和 15 号核验规则创建关联复检任务，显示 7 项核验结果。沿用既有文件登记与检测接口，原送审稿和首次核验记录保留；属于与招标文件修复相同的预置样例处理流程。

招标检测报告提供“一键大数据 AI Agent 修复”：约 6 秒展示修复进度，登记预置的 `09_招标文件_发布版.docx` 并自动下载，以配套样例基准及 07 号规则重新检测，关联原报告并保留两次记录。前端复用现有文件登记、规则查询和检测任务接口，不依赖新增加的修复接口，兼容尚未重启的服务。此按钮是演示流程，使用预置发布版，不会调用真实模型改写任意文件；正常真实 AI 问答不受影响。同一登录期间重复点击同一原任务复用已生成的发布版和复检记录。

初稿和审核函使用富文本排版编辑器：支持加粗、斜体、下划线、三级标题、项目符号、编号列表、左对齐和居中；表格直接显示为网格，可编辑单元格、插入表格、增行增列和删除行。两份材料均可修改，保存为新版本后可下载包含文字、基础格式与表格的 DOCX。复杂合并单元格调整可在 Word 中完成。本次按用户要求未运行测试，交由用户验证。

项目列表的“删除”操作由业务人员、审核人员或管理员使用，确认后将项目移出列表并停止其相关接口访问；原件及审计记录保留。监督及代理账号无删除权限，有正在执行任务时需等待任务结束。

招标文件编制的“生成初稿与审核函”展示至少 48 秒的分阶段处理进度，完成后才显示生成结果。

每次登录从空白状态开始：项目列表保留，文档和各类历史结果初始隐藏。点击“上传文档”后真实选择本地文件，页面展示约 10 秒的处理窗口，结束后仅显示所选材料。当前演示上传仅传递文件名、大小等元数据，**不读取、不上传、不解析所选文件的内容**：与 check_docs 同名的文件复用已有样例快照，其他文件仅登记元数据，不能从其内容生成真实分析结果。原有真实解析接口保留，但页面的上传按钮不会调用它。开始检测后才显示本轮报告。刷新保留本轮展示，退出再登录重新隐藏；已删除侧栏重演入口及页面上的“模拟／演示”提示。上述行为用于产品演示，不能作为所选任意文档已完成真实分析的依据。

1. 登录后进入项目库，点击查看详情管理材料。可上传、预览、下载、确认基准、调整类别及撤下／恢复。每次上传产生新版本，原件保留。
2. 招标编制自动选取项目、资格、技术、合同、模板及审核函，生成可编辑初稿与审核函 DOCX。初稿明确列出待填项；编辑保存产生新版本。
3. 招标检测选择 08，运行得到 14 通过、1 不通过。展开 R09 查看 08 中 3 个案例和 03 中 1 个案例，点击证据跳转原文位置。
4. 确认问题单、发送站内整改通知；同一问题重复发送去重。代理可上传修订版本、提交反馈。选择 09 复检得到 15 通过，问题自动关联复检并关闭。历史任务与文档快照保留。
5. 撤下 03 再运行 08，R09 为无法核验。恢复后可重新执行。复检默认复用原任务基准及规则快照，新检测使用当前有效基准。
6. 评标报告核验选择 16 得到 6 通过、1 不通过，E04 同时展示推荐意见 92 分和汇总表 89 分。17 得到 7 通过。
7. 投标辅助评审生成四家 Q01–Q03、T01–T05 响应矩阵及双侧相似证据；A、B 技术方案命中长段与“申批回朔”。线索支持人工排除并留痕。共同模板另行标记，不用于自动认定。
8. 制度问答默认检索制度材料，签字问题引用模拟制度第 7 条，保留原文位置。可选择模型整理答复。
9. 发布登记需选已确认且通过检测的招标版本、清理未关闭问题，再录入平台、链接、期限、费用。定标页汇总报告候选人及证据，报告确认且问题关闭后可登记决定并归档。审计页导出 JSON 材料包。

## 自动文档隔离

路由在服务端按项目权限、环节类别、确认状态、有效性及最新确认版本筛选。每个环节显示选用材料和被屏蔽原因。同类其他目标版本（如检测 08 时的 09）不参与检查；评标报告、投标文件、规则与制度语料各用其适用范围。验收说明文件不参与检测。历史报告固化文件哈希、原文片段、基准、规则与解析版本。

## 当前实现边界

- DOCX 按真实章节、段落及表格行定位，**尚未实现固定渲染分页**，不会虚构页码。PDF 文本解析保留页码及文字坐标。
- 扫描 PDF 低文字页标记解析质量不足。可通过 `OCR_COMMAND` 接入本地 OCR 可执行程序：参数为 PDF 路径，标准输出为 `{ "pages": [{"page":1,"text":"识别内容"}] }`。没有内置 OCR 模型；当前样例均为 DOCX，扫描件尚未联调。
- 确定性规则针对提供的材料结构实现；自定义规则需要模型或人工核验。语义正确性、资质真实性、电子签章真伪和围串标结论由授权人员确认。
- 通知为本地站内通知；未向真实代理发送消息。OA、招采平台、统一认证和档案接口未接入。权限为固定演示账号与项目成员校验，未提供完整组织权限配置界面。
- 大文件解析目前在 Node 服务进程完成，尚未实现独立解析工作进程和生产级并行压测。制度采用本地片段检索；当前不存在向量库或自动法规更新。
- 人工结论作为独立记录留存，原检测结果不覆盖。发布和归档门禁仍以实际复检通过及问题关闭为依据。
